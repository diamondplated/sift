# SwiftUI App Implementation Plan (Native Sift, Plan 4 of 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `web/index.html` and `shell/**` with a native SwiftUI window — sources sidebar, `NSTableView` grid, column inspector, filter toolbar, SQL console, and every sheet — driven directly by the `SiftEngine` actor. At the end of this plan Sift is a Mac app with no WKWebView, no loopback server, and no JavaScript.

**Architecture:** Two new targets. **`SiftUI` is a library** holding every view, every view model and every decision; **`SiftApp` is an `executableTarget`** holding `@main`, the menu bar, the toolbar and LaunchServices document handling, and nothing else. That split is not taste — a SwiftPM test target cannot import an `executableTarget`, so anything that lands in `SiftApp` is permanently untestable. `Tests/SiftUITests` covers `SiftUI`.

**Tech Stack:** Swift 6, SwiftPM, swift-testing, SwiftUI, AppKit, `SiftEngine`, `SiftCore`, `DuckDBKit`.

**Spec:** `docs/superpowers/specs/2026-08-09-native-sift-design.md` §4, §7, §9, §10, §11, §13a, §14.

**Plan sequence:** 1 DuckDBKit ✅ → 2 SiftCore ✅ → 3 SiftEngine + CLI ✅ → **4 Grid + panels (this)** → 5 Bundle and delete.

## Global Constraints

- Swift tools version **6.0**. Platform floor **macOS 14**. Zero third-party dependencies. Pure SwiftPM — no Xcode project, ever.
- `SiftUI` and `SiftApp` may import `SiftEngine`, `SiftCore`, `DuckDBKit`, SwiftUI and AppKit. **`SiftCore` stays Foundation-only** — never add an import to it.
- **`SiftApp` is an `executableTarget`, so no test can import it.** `main.swift`, `AppDelegate.swift` and the menu/toolbar builders live there; every decision, every transformation and every piece of state lives in `SiftUI`. If you find yourself wanting to test something in `SiftApp`, it is in the wrong target — move it down.
- **No `NumberFormatter` / `DateFormatter` / `ISO8601DateFormatter` / `Text(_, format: .number)` / `.formatted()` for anything a user or a test sees.** They follow `Locale.current`. Three bugs of exactly this shape have already shipped on this branch. Hand-roll it, or use the engine's renderer (Task 3), which is locale-independent by construction.
- **This Mac has only the macOS 26 SDK, so it is a bad oracle.** Code that compiles here can fail for everyone else. CI on `macos-15` is the only real check. Prefer APIs available on the macOS 14 floor — see "Newer APIs that must not be used" below.
- Every commit leaves `swift build && swift test` green and **warning-free**, including the existing DuckDBKit / SiftCore / SiftEngine suites. Suites run **in parallel**; do not introduce anything needing `.serialized`.
- **Any script committed here needs `git add --chmod=+x`** — this repo has `core.fileMode=false` (its `.git` is on an SMB share), so a plain `chmod +x` records mode `100644` and CI dies on a fresh clone. Verify with `git ls-files -s <path>` showing `100755`.
- **`setSpec`, `exitSQLMode` and `renderedSQL` return values and are not `@discardableResult`.** Every call-for-effect needs `_ = try await …` or the build is not warning-free. (`stageNow`, `cancel`, `unstage`, `purgeStaged`, `merge` and `export` *are* `@discardableResult`.)
- Commit as the repo's configured identity. **Never `git reset`, `git checkout --`, or `git stash`** on this branch — a concurrent session shares the underlying repository.
- Do not touch `engine/`, `web/`, `shell/`, `dev.sh`, `bin/sift-open`, `requirements*.txt`, `pytest.ini`, or the legacy files at the repo root. They are deleted in Plan 5, not before.
- **Edits to `SiftEngine` are permitted only where a task names them.** Three tasks do (Task 2's open-home guard, Task 5's sort cap, Task 12's staging-policy accessors), and each says exactly what it adds. Nothing else in `Sources/SiftEngine/**`, and nothing at all in `Sources/SiftCore/**` or `Sources/DuckDBKit/**`.

## Concurrency model — decided here, not per task

`Session` is an `actor` and **every read is an `await`**. The view layer's rule, in four facts:

1. **`AppState` and every view model are `@MainActor @Observable` classes.** SwiftUI observes them directly. They are the only mutable UI state.
2. **Everything that crosses the boundary is already `Sendable`** — `Table`, `TablePage`, `Cell`, `SessionState`, `EngineInfo`, `ColumnProfile`, `DistinctPanel`, `HistogramPanel`, `BadRowsPanel`, `StagedSource`, `LengthBucket`. No new bridging type is needed and none may be added. `Connection` and `ResultSet` never leave `SiftEngine`.
3. **Scrolling never spawns a task per block.** One `PageLoader` per open table runs a single-flight pump: it holds a *set* of wanted block indices, fetches the one nearest the viewport centre, delivers it, and repeats. Scrolling past a block removes it from the set before it is ever requested. This is the native equivalent of the web grid's `AbortController` map (`web/index.html:809-868`), and it is strictly better here — see the landmine below for why per-block `Task.cancel()` would not have worked.
4. **The engine is polled, not subscribed.** SSE is gone and `Session` has no change channel. `AppState` calls `await session.state()` on an adaptive cadence: **250 ms** while anything is in flight (`counting`, `staging != nil`, `profiling`), **2 s** otherwise, plus an immediate refresh after every user action. Considered and rejected: adding an `AsyncStream` to `Session`. It is a real engine change that does not fix the one thing that actually stalls the UI (the actor blocking inside `page`, fact 3 of `Session.swift`'s header), and `state()` is a snapshot of a handful of structs.

> **Fact 3 was corrected 2026-08-11** (engine whole-plan review, finding 5), and this plan cites it by name as its concurrency contract, so read the corrected version rather than a remembered one. `pagingConnection` has **six** users, not the three the old text named — `page`, `sortedRelation`, `closeTable`, plus `applyStaged`, `finishStage` and `unstage` — and the invariant is **per-use, not per-method**: no user may suspend *between acquiring the connection and finishing with it*. `unstage` is `async` and does `await`, just after it is done with the connection, which the old "these methods never await anything" wording made look forbidden. Nothing in this plan changes as a result; the contract it relies on (one caller inside at a time, so the UI never races the engine on that connection) still holds.
>
> `state()` also **sorts by `openedAt` as of the same review** (finding 1). It used to return `Array(tables.values)`, i.e. `Dictionary` order — measured different on every launch. Tab order, sources-list order and the default selection therefore now follow the order the user opened files in, which is what this plan's views already assume.

## 🔴 Landmines — read before writing any code

**`Task.cancel()` does not cancel an actor call.** `await session.page(...)` runs to completion on the actor whether or not the calling `Task` was cancelled; `Session.page` never checks `Task.isCancelled` and never suspends. Cancelling a per-block task therefore only **discards** the result — the work still happens, still queues on the actor, and still delays the block the user is actually looking at. That is why Task 4 is a single-flight pump with a mutable want-set rather than a task per block. Say "discarded", never "cancelled", in comments.

**A public struct's memberwise initializer is `internal`.** `TablePage`, `TablePage.ColumnInfo`, `DistinctPanel`, `DistinctPanel.Value`, `HistogramPanel`, `HistogramPanel.Bucket`, `BadRowsPanel`, `LengthBucket`, `StagedSource`, `PurgeResult`, `EngineInfo` and `SessionState` all declare `public let` fields and **no `public init`** — so `SiftUI` and `Tests/SiftUITests` can read them but **cannot construct them**. Consequences, both load-bearing:
- The view models must use **`SiftCore.Column`** (which does have `public init(name:type:)`) as their column type, converting with `Column(name: info.name, type: info.type)`. `Column.init` recomputes `kind` through the same `kind(of:)` the engine used, so the value is identical.
- Any test that needs a `TablePage`, a `DistinctPanel` or a `HistogramPanel` must get it from a **real `Session` over a real fixture**. Do not add `public init`s to the engine to make a test easier. `PageLoader` is generic (Task 4) precisely so its own tests can use a payload they *can* build.

Types that **are** constructible, and which tests should use freely: `Cell`, `Column`, `Table`, `SourceSpec`, `SourceKey`, `QuerySpec`, `QuerySpec.SortTerm`, `Filter`, `SQLValue`, `ColumnProfile`, `StageDecision`, `StagingProgress`, `SheetInfo`, `RowEstimate`.

**`Cell.display` is lossy on purpose** (its own doc comment says so): it renders `.null` and `.text("")` identically as `""`, collapsing two of the three states — NULL, `''`, `'N/A'` — that spec §9 calls non-negotiable. The grid **must** switch on the `Cell` case for that distinction and use `display` only for the glyph. Never `String(describing:)` a `Cell`.

**`Cell.decimal` carries its scale** — `case decimal(Decimal, scale: Int)`. `Cell.display` already re-pads it, so a `DECIMAL(10,2)` renders `10.50`. Do not re-format a decimal in the view layer; you will get `10.5`.

**`Cell.list([Cell])` exists and every `switch` over `Cell` must handle it.** The bad-rows sheet matches on `.list` directly to get the failing column names — it must not re-split `display`'s joined text.

**Non-`async` actor methods still need `await`.** `setSpec`, `exitSQLMode`, `renderedSQL`, `snippet`, `stageNow`, `cancel`, `stagedEntries`, `purgeStaged` and `table(_:)` are declared `throws` (or plain) rather than `async`, but every call from outside the actor is still `try await session.setSpec(...)`. `engineInfo()`, `stagedTotalBytes()`, `relation(_:)` and `dropPrivateStore()` are `nonisolated` and need no `await`.

**Newer APIs that must not be used** — tempting, and all above the macOS 14 floor. This Mac will compile them; `macos-15` will not:
- `onGeometryChange(for:of:action:)` (macOS 15) — use `GeometryReader`.
- `@Entry` for `EnvironmentValues` (macOS 15) — write the `EnvironmentKey` by hand, or pass the value down explicitly.
- `TabView(role:)` / the `Tab` type (macOS 15) — the inspector's three tabs are a `Picker` with `.pickerStyle(.segmented)`.
- `MeshGradient`, `.symbolEffect(.wiggle)`, `.scrollBounceBehavior` refinements, `WindowDragGesture` (macOS 15), anything Liquid Glass (`.glassEffect`, `.buttonStyle(.glass)`, macOS 26).
- `Table`/`TableColumnForEach` from SwiftUI — available, but wrong: it needs a `RandomAccessCollection` of *every* row. Spec §9 forbids it.

Safe and used: `NavigationSplitView` + `NavigationSplitViewVisibility`, `.inspector(isPresented:)`, `@Observable`, `ImageRenderer`, `.contextMenu`, `.searchable` is **not** used (the value search is a plain `TextField`, matching `web/index.html:1235`).

```swift
import DuckDBKit
import Foundation
import Observation
import SiftCore
import SiftEngine
import SwiftUI

@MainActor
@Observable
public final class AppState {
    public let session: Session
    public let engine: EngineInfo

    /// Mirror of the actor's catalog, refreshed by `poll()`. Read-only for views.
    public private(set) var tables: [Table] = []
    public var activeName: String?
    /// Bound to `NavigationSplitView(columnVisibility:)` in `RootView`, and flipped by View >
    /// Toggle Sidebar (Task 13). SwiftUI owns the split now, so this replaces the shell's
    /// `NSSplitViewController.toggleSidebar`.
    public var sidebarVisibility: NavigationSplitViewVisibility = .all
    /// Bound to `.inspector(isPresented:)` (Task 8) and flipped by View > Toggle Inspector.
    public var inspectorVisible = true
    /// One user-facing sentence, or nil. Python emitted `{"type": "error"}`; there is no SSE, so
    /// the banner IS the notification.
    public var banner: String?

    private var models: [String: TableViewModel] = [:]
    private var pollTask: Task<Void, Never>?

    public init(session: Session) {
        self.session = session
        self.engine = session.engineInfo()   // nonisolated
    }

    public var active: Table? { tables.first { $0.name == activeName } }

    public func open(path: String, sheet: String? = nil) async {
        do {
            let t = try await session.openPath(path, sheet: sheet)
            await refresh()
            activeName = t.name
        } catch {
            banner = error.localizedDescription
        }
    }

    public func close(_ name: String) async {
        do { try await session.closeTable(name) } catch { banner = error.localizedDescription }
        models[name] = nil
        await refresh()
        if activeName == name { activeName = tables.first?.name }
    }

    public func refresh() async {
        let snapshot = await session.state()
        tables = snapshot.tables.sorted { $0.openedAt < $1.openedAt }
        if let activeName, !tables.contains(where: { $0.name == activeName }) {
            self.activeName = tables.first?.name
        }
        for t in tables { models[t.name]?.apply(t) }
    }

    /// One view model per open table, created lazily and kept so the page cache survives a tab
    /// switch — the web build cleared its blocks on every switch and re-fetched (`resetGrid`).
    public func model(for name: String) -> TableViewModel? {
        guard let t = tables.first(where: { $0.name == name }) else { return nil }
        if let existing = models[name] { return existing }
        let m = TableViewModel(session: session, table: t)
        models[name] = m
        return m
    }

    /// Adaptive polling replaces SSE. 250 ms while the engine is doing something the user is
    /// waiting on, 2 s otherwise. Every user action calls `refresh()` directly as well, so this
    /// only has to catch *background* progress: the exact count, bad-row detection, the profile,
    /// and a staging job.
    public func startPolling() {
        pollTask?.cancel()
        pollTask = Task { [weak self] in
            while !Task.isCancelled {
                guard let self else { return }
                await self.refresh()
                let busy = self.tables.contains {
                    $0.counting || $0.staging != nil || $0.profiling
                }
                try? await Task.sleep(nanoseconds: busy ? 250_000_000 : 2_000_000_000)
            }
        }
    }

    public func stopPolling() { pollTask?.cancel(); pollTask = nil }
}
```

```swift
import Foundation

/// A temp directory removed when the test scope ends.
func tempDir(_ name: String = UUID().uuidString) throws -> URL {
    let url = FileManager.default.temporaryDirectory
        .appendingPathComponent("siftui-\(name)", isDirectory: true)
    try FileManager.default.createDirectory(at: url, withIntermediateDirectories: true)
    return url
}

/// A CSV with a numeric, a text and a deliberately three-state column: a real NULL (missing
/// field), a real empty string, and the literal sentinel "N/A". Those three staying distinct is
/// the product's whole premise (spec §9), and every rendering test needs a row of each.
@discardableResult
func makeCSV(in dir: URL, name: String = "t.csv", rows: Int = 12) throws -> String {
    var out = "id,label,note\n"
    for i in 0..<rows {
        let note = i % 3 == 0 ? "" : (i % 3 == 1 ? "\"\"" : "N/A")
        out += "\(i),row\(i),\(note)\n"
    }
    let path = dir.appendingPathComponent(name).path
    try out.write(toFile: path, atomically: true, encoding: .utf8)
    return path
}
```

### Task 2: Close the two-`Session` corruption hazard (spec §13a)

**Files:** Create `Sources/SiftEngine/OpenHomes.swift`, `Tests/SiftEngineTests/OpenHomesTests.swift`. Modify `Sources/SiftEngine/Session.swift`, `Tests/SiftEngineTests/StagingTests.swift`. Modify the spec.

**Interfaces:**
- Consumes: nothing.
- Produces: `Session.init` throws `SessionError` when another **live** `Session` in this process holds the same `SIFT_HOME`; `Session.shutdown()` and `deinit` release the claim, and only their own.

**Why this is Task 2 and not Task 12.** Spec §13a: two `DuckDBKit.Database` handles opened on the same file *in one process* are two independent DuckDB instances with no shared catalog — A inserts and checkpoints, A sees 2, **B still sees 1**, and B's next flush writes its version over A's file. Last flush wins, silently. The `sharedStore` fallback does not help: it fires only on a DuckDB *lock* error, and there is no lock error in-process, which is exactly why both sessions in the measurement reported `sharedStore=true`. Nothing constructs two today — Task 1 builds exactly one — but the guard has to exist before anything (a preferences rebuild, a second window, a test opening two on one home) makes it live, and "the UI is what would construct the second" is why §13a assigns it here.

**🔴 The claim must carry a token, not just a path.** A path-keyed `release(_:)` called from both `shutdown()` and `deinit` defeats the whole guard on this sequence, which is the *normal* lifecycle, not an edge case:

```
A.shutdown()          → releases "home"
B = Session("home")   → claims "home"      (legitimate — A is done)
A deallocates         → A.deinit releases "home"  ← releases B's claim
C = Session("home")   → succeeds, and now B and C are corrupting each other
```

So the registry stores `[String: UUID]` and `release` removes the entry **only when the token matches**. `Session` carries a `nonisolated let claimToken = UUID()` for that. Do not write a comment claiming a stale release is impossible — it is possible precisely *because* the claim is keyed by path, and the token is what makes it detectable.

```swift
import Foundation

/// Process-wide registry of the `SIFT_HOME` paths a live `Session` is holding, and which session
/// holds each.
///
/// Spec §13a: two `Database` handles on one file *in one process* are two independent DuckDB
/// instances that cannot see each other's catalog, so the second one's flush silently overwrites
/// the first one's. That is not lock contention — measured, there is no lock error in-process at
/// all, which is precisely why `Session`'s `sharedStore` fallback never fires for it and reports
/// `true` for both. The only thing that stops it is refusing the second open.
///
/// The value is a token, not a bool, because `release` is called from BOTH `shutdown()` and
/// `deinit` and those can straddle a legitimate hand-over: A shuts down, B claims the same home,
/// then A deallocates. A path-keyed release cannot tell that the entry it is about to remove now
/// belongs to B, so it would hand the home to a third session while B is still writing to it.
/// Comparing the token is what makes that case detectable.
///
/// `@unchecked Sendable` with an explicit lock rather than an actor: `Session.init` is a
/// synchronous throwing initializer and cannot `await`.
final class OpenHomes: @unchecked Sendable {
    private let lock = NSLock()
    private var owners: [String: UUID] = [:]

    /// `true` if `token` took ownership; `false` if someone else already holds `path`.
    func claim(_ path: String, token: UUID) -> Bool {
        lock.withLock {
            guard owners[path] == nil else { return false }
            owners[path] = token
            return true
        }
    }

    /// Release only a claim this token actually holds. Idempotent, and deliberately a no-op for a
    /// path now owned by someone else — see the type's doc comment for the sequence that makes
    /// that distinction load-bearing.
    func release(_ path: String, token: UUID) {
        lock.withLock {
            if owners[path] == token { owners[path] = nil }
        }
    }
}
```

```swift
@MainActor
public final class PageLoader<Payload> {
    /// Not `@Sendable` — see this task's header. The closure is stored and called only on the
    /// MainActor and never crosses an isolation boundary.
    public typealias Fetch = (Int) async throws -> Payload

    public var onDeliver: ((Int, Payload) -> Void)?
    public var onFailure: ((Error) -> Void)?
    /// Bumped by `invalidate()`. A delivery whose generation no longer matches is dropped: the
    /// filter, sort, staged-ness or table changed while it was in flight, so it describes rows
    /// that are no longer what the grid is showing.
    public private(set) var generation = 0

    private let fetch: Fetch
    private var wanted: [Int] = []
    private var centre: Double = 0
    private var pump: Task<Void, Never>?

    public init(fetch: @escaping Fetch) { self.fetch = fetch }

    /// Replace the want-set. Nearest-to-`centre` wins, so the rows actually on screen are fetched
    /// before the overscan around them.
    public func request(blocks: [Int], centre: Double) {
        self.centre = centre
        for b in blocks where !wanted.contains(b) { wanted.append(b) }
        wanted.removeAll { !blocks.contains($0) }
        startPumpIfIdle()
    }

    public func invalidate() {
        generation += 1
        wanted.removeAll()
    }

    private func startPumpIfIdle() {
        guard pump == nil else { return }
        pump = Task { [weak self] in
            while let self, let block = self.takeNearest() {
                let stamp = self.generation
                do {
                    let payload = try await self.fetch(block)
                    // Not "cancelled" — `Task.cancel()` does not stop an actor call, so the work
                    // has already happened. This only stops it being shown for a spec that is no
                    // longer on screen.
                    if stamp == self.generation { self.onDeliver?(block, payload) }
                } catch {
                    if stamp == self.generation { self.onFailure?(error) }
                }
            }
            self?.pump = nil
        }
    }

    /// The wanted block closest to the viewport centre, removed from the set.
    private func takeNearest() -> Int? {
        guard let best = wanted.min(by: {
            abs(Double($0) - centre) < abs(Double($1) - centre)
        }) else { return nil }
        wanted.removeAll { $0 == best }
        return best
    }

    /// Test seam: awaits the pump so a test can assert on what was fetched. `internal`, reached
    /// through `@testable import` — it exists for the suite and has no place in the app.
    func drainForTest() async { await pump?.value }
}
```

A thrown error goes to `onFailure` and the pump continues to the next block — one bad page must not wedge the grid.

#### 5a. The extent is `nil` for every text file until the background count lands

`visibleRows` is `nil` until `rowCount` is set, and `Session.openPath` sets `rowCount` only from `spec.rowCount`. `buildSource` populates that for parquet, glob-parquet, Delta, xlsx, JSON, and CSV **under the small-file threshold** — and leaves it `nil` for every larger CSV, where it fills `rowEstimate` instead. Sizing the grid from `visibleRows` alone therefore ships an **empty grid on open for exactly the large text files the product exists to open instantly**, until a detached background count finishes. It also makes any test asserting on the extent a race against that task.

**The shipping app already solved this and the port dropped it.** `Table.summary()` (`engine/session.py`) returns `rows.value = visible_rows if visible_rows is not None else est.rows`, with `exact = row_count is not None` and a three-branch `basis`; the web grid sets `state.total` straight from it (`web/index.html:551`). Port that, on `Table`, where the three consumers (the grid extent, the sidebar's `rowText`, the Source tab's basis line) all read one definition rather than three.

#### 5b. A sorted table over 5,000,000 rows silently drops its tail (spec §13a)

`Session.sortedRelation` always materializes and materializes at most `sortMaterializeMax` (5,000,000) rows. Pages past that return **empty** while the row count still reports the full total — so a sorted 100M-row table sizes its extent for 100M and 95M of them come back blank. §13a names two fixes.

**Take option one: cap the reported extent, and say so on screen.** Reasons, in order:
1. Re-materializing a window as the user scrolls reintroduces exactly the bug materialize-once exists to prevent. `sortedRelation`'s own doc comment records the measurement: re-sorting the same static, tie-bearing table at different `LIMIT`/`OFFSET` pairs does **not** reproduce the same tie order — 4 rows out of 1000 landed on two pages and 4 on none. Two separately materialized windows have that same seam, and a duplicated-or-dropped row in a tool whose premise is not lying about data is worse than a missing tail.
2. Making windowing correct needs a total order — appending every column as a tiebreak — which changes what the user asked to sort by, and still pays a full sort per window.
3. Capping makes the extent *true*: everything the thumb can reach returns rows. The tail is not silently missing, it is named in a banner with the way to reach it (clear the sort).

Deliberately not raising `sortMaterializeMax`: it is Python's number, ported verbatim, and 5M rows of materialized copy is already the memory ceiling the engine chose.

#### 5c. Nothing in the app ever computes a profile

`runAfterOpen`'s doc comment says outright that `compute_profile`'s eager trigger is the one step of Python's `_after_open` it does not port, and the only caller of `computeProfile` in the tree is `merge`. So without a kick from the UI: column widths sit on the 120-pt fallback forever, sort carets and distinct counts and missing bars never appear, the Schema tab renders empty rows, and the Column tab has no stats. The web called `loadProfile()` after the first block landed on every table load (`web/index.html:557`) and re-ran `renderHead()` when it arrived. `TableViewModel` does the same.

**🔴 RESOLVED 2026-08-11 (engine whole-plan review, finding 4) — the kick is the UI's, the COST GATE is not, and `kickProfile()` must call the gated entry point.** This section as written kicks a profile after the first page with **no gate at all**. Python gates its eager profile on `size <= PROFILE_EAGER_MAX_BYTES (200 MB) or staged or columnar` (`session.py:454`), and the port had carried neither the constant nor the check — so the native app would `SUMMARIZE` a 30 GB CSV that Python deliberately skips: minutes of full scan for a panel nobody has opened, the profiling-path version of the "a drive-by peek must not pay for the copy" rule `shouldStage`'s dwell enforces for the copy.

The engine now owns the policy and exposes the gated call:

- `SiftCore.shouldProfileEagerly(fmt:sizeBytes:staged:)` and `SiftCore.profileEagerMaxBytes` — beside `shouldStage`, so both consumers read one policy rather than re-deriving it.
- `Session.profileIfCheap(_ name:) async throws -> Bool` — applies the gate and computes only if it passes; returns `false`, having done nothing, if not.

**`TableViewModel.kickProfile()` calls `session.profileIfCheap(name)`, never `computeProfile`.** There is no ungated speculative call to reach for, which is the point — the gate cannot be forgotten. `profileOf` / `distinct` / `histogram` stay ungated, exactly as Python leaves `profile_of`: a user clicking a column on a 30 GB file is asking, and refusing a direct request would be a different product. Nothing else in this section changes; a table that fails the gate simply has no profile until the user opens a panel, and `Table.profiling` stays `false` throughout.

**`computeProfile` is being detached in the engine, in a separate worktree — this plan consumes the result and must not pre-empt it.** Measured 2026-08-09 with the DuckDB CLI (v1.5.2 — the vendored engine is 1.5.5, so treat these as indicative of shape, not exact), running `computeProfile`'s two queries against synthetic tables:

| shape | `SUMMARIZE` | the `profileExtraSQL` pass | total actor hold |
|---|---|---|---|
| 20 cols × 200,000 rows | 0.102 s | — | ~0.12 s |
| 200 cols × 10,000 rows | 0.109 s | — | ~0.13 s |
| 20 cols × 2,000,000 rows | 0.310 s | — | ~0.35 s |
| **200 cols × 200,000 rows** | **1.108 s** | **0.185 s** | **~1.29 s** |

Cost scales roughly with columns × rows, and **every shape measured is already at or past ~100 ms**; the realistic wide case is ten times it. Both caveats push it further up, not down — the figures exclude `DuckDBKit`'s chunk decoding of a 200-column `SUMMARIZE`, and came from the 1.5.2 CLI rather than the vendored 1.5.5. Because the current `computeProfile` never suspends, that is the whole actor unavailable: a visible hang on open for a wide file, spec §13a's page-latency cliff in a second location.

**Resolved in the engine, not here.** `computeProfile` is being moved to a detached `Task` with its own `Connection`, applying results back through an isolated `applyProfile(_:openedAt:)` that follows the `applyCount` / `applyBadRows` / `applyStaged` pattern the engine already uses three times, with the same open-generation guard. The UI-only alternative — deferring the kick until the grid is idle — was rejected: it relocates the stall to the moment the user stops moving, which is exactly when they are about to scroll again.

**RESOLVED 2026-08-11 — how `profileOf`, `distinct` and `histogram` behave now profiling is asynchronous.** The engine change shipped (`ced8df7`, then hardened by the whole-plan review's finding 4). The contract, which downstream tasks may now rely on:

1. **`computeProfile` never returns the detached task's own value.** It kicks or joins a job, then reads back what `applyProfile` *accepted* — so what a caller holds and what the catalog caches are the same object by construction, not by agreement. Bounded at five passes; a normal profile costs two.
2. **A caller whose table moved under it gets the current table's profile**, not the dead generation's. The panels ask by name, and name is the identity the whole engine uses. This closed a real hole: before it, a profile job bound its relation by name and resolved it *when the query ran*, so closing a tab mid-panel returned another file's numbers as if they were fine.
3. **A caller whose table is gone gets `No open table named 'x'.`** — one clean sentence, never a catalog dump. `distinct` used to swallow that with `try?` and then query a dropped relation, surfacing `Catalog Error: Table with name x does not exist!` on every column click during a close; that is fixed too.
4. **`kickProfile()` is fire-and-forget and must call the gated entry point** — `Session.profileIfCheap(_ name: String) async throws -> Bool`, which applies `SiftCore.shouldProfileEagerly(fmt:sizeBytes:staged:)` and returns whether it actually profiled. `computeProfile` and `profileOf` stay **ungated**, exactly as Python leaves `profile_of`: a panel the user opened is not speculative. The speculative entry point *is* the gated one, so there is no ungated speculative call to reach for by accident.
5. **Coalescing is real and pinned**: a speculative kick and a panel's `profileOf` moments later share one `SUMMARIZE` rather than paying twice.

**The UI reads `Table.profiling` — the engine flag — and there is no view-model mirror of it.**

That is worth spelling out because it is a *reversal*, and the reasoning behind the reversal is the same reasoning that produced the measurement. Against the **current** engine, `Table.profiling` cannot be observed as `true` by anybody: `computeProfile` contains no suspension point (verified — the only `await`s in `SessionQueries.swift` are same-actor calls that do not suspend), so it holds the actor for its whole duration and publishes `profiling = false` in its `defer` before any other actor call can run. Publishing the flag earlier would not change that; the flag would have had to live on the `MainActor`, the same shape as `BusyState` in Task 10.

**Detaching `computeProfile` is exactly what makes it observable.** With the work off the actor, a poll can land mid-flight and see `true`. So the flag becomes real, and the UI takes it rather than mirroring it: it is the authority, it is already `public`, and one flag beats two that can disagree. `AppState`'s poll predicate keeps `$0.profiling`; Task 8's "Profiling…" note reads `table.profiling`.

`TableViewModel` therefore keeps only a `private var profileTask: Task<Void, Never>?`, purely as a re-entrancy guard — a handle it wants regardless, and one that makes no claim about what the engine does internally, which the PENDING note above forbids.

```swift

    /// the cheap byte-sample estimate. Ports `Table.summary()`'s `rows.value`
    /// (`visible_rows if visible_rows is not None else est.rows`).

    /// The fallback is not cosmetic. `openPath` sets `rowCount` only from `spec.rowCount`, which
    /// `buildSource` leaves nil for any CSV above its small-file threshold — so without this a
    /// multi-GB CSV shows an EMPTY grid from open until a detached background count finishes,

    /// Whether `displayRows` is counted or estimated. `summary()`'s `rows.exact`.

    /// How `displayRows` was arrived at. `summary()`'s `rows.basis`, all three branches — but as
    /// a value, not a sentence.
    ///
    /// Python returned the literal string because its engine served exactly one consumer. This
    /// engine has two (`SiftUI` and the `sift` CLI), which want different phrasing, and keeping
    /// user-facing sentences out of `SiftEngine` means a wording change never touches the engine.
    public enum RowsBasis: Sendable, Equatable {
        case counted
        /// The byte-sample estimator's own description, e.g. "3x256KiB sample, no quotes seen".
        case estimated(String)
        case pending
    }

        if rowCount != nil { return .counted }
        if let basis = spec.rowEstimate?.basis { return .estimated(basis) }
        return .pending

    /// `Session.sortedRelation` will have materialized.
    ///
    /// Spec §13a: a sorted result set is materialized once, at most `sortMaterializeMax` rows, and
    /// pages past that come back EMPTY while the count still reports the full total. Sizing the

    /// rejected: `sortedRelation`'s own measurement shows tie order is not reproducible across
    /// separate materializations, so two windows can duplicate or drop rows at their seam.
    public var scrollableRows: Int? {
        guard let rows = displayRows else { return nil }
        return qspec.sort.isEmpty ? rows : min(rows, sortMaterializeMax)

    public var sortTruncated: Bool {
        guard !qspec.sort.isEmpty, let rows = displayRows else { return false }
```

```swift
    private func kickProfile() {
        guard profileTask == nil, profile.isEmpty else { return }
        profileTask = Task { [weak self] in
            guard let self else { return }
            self.profile = (try? await self.session.computeProfile(self.name)) ?? []
            self.profileTask = nil
            self.onProfileArrived?()
        }
```

**The §13a paging cliff, and what the UI shows.** `Session.page` runs synchronously on the actor and never suspends, so the first sorted page over a large table blocks **every other actor call** for as long as the materialization takes — `table`, `state`, a second `openPath`, and every background callback all wait. `Session.page`'s own doc comment records this as a deliberate, un-fixed cliff and says the grid must show a busy state across it.

2. **`BusyState` flips visible after 400 ms.** `begin` schedules a `Task` that sleeps 400 ms and then sets `visible = true` unless `end()` already ran. **This works only because `BusyState` is on the `MainActor`, which is not the actor that is blocked** — a flag the blocked actor had to set would arrive after the stall it was meant to announce.
